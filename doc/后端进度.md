## 4. 必须先修的技术债

这些问题会影响真实数据含义，应优先于继续扩展新页面。

### P0：学生状态编码错位（2026-10-09 已修复代码口径，存量数据待核对）

已统一为 `0在读 / 1休学 / 2转学 / 3毕业`：VO 入参/出参均为字符串，PC 端筛选、默认值、提交、标签同步修改。
存量数据：修复前 PC 端新建学员会写入 `'1'`（前端本意“在读”），上线前需人工核对并回填。

原问题：真实库和代码存在学生 `status` 口径不一致：

- DO/真实表口径：`0在读 / 1休学 / 2转学 / 3毕业`
- VO/部分前端口径：`1在读 / 2休学 / 3转学 / 4毕业`

风险：

- 新建学生可能写入错误状态
- 在读筛选可能查不到真正的在读学生
- 后续统计会持续出错

需要：

- 统一 DO、VO、前端筛选值
- 出存量数据回填脚本
- 补测试或 smoke 校验

### P0：考勤状态跨表串味

当前存在两套状态：

- `teach_class_attendance_detail.status`：`1到课 / 2迟到 / 3请假 / 4未到`
- `teach_schedule_attendances.status`：`0未到 / 1出勤 / 2迟到 / 3请假 / 4缺勤`

风险：

- 班级点名反写课表考勤时语义不清
- 未到、缺勤、请假统计可能混乱

需要：

- 明确两套表是否继续并存
- 若并存，增加显式枚举映射
- 统一前端展示文案和统计口径

### P1：旧表软删值不统一

部分旧表 `del_flag` 使用字符约定，但 DAO 写入数字值。

风险：

- MySQL 下可能靠隐式转换侥幸可用
- 换库或写报表时容易漏判

需要：

- 统一旧表删除值
- 修正 DAO 写法
- 检查存量脏值

### P1：悬空接口清理

已知前端有调用但后端缺接口：

- 老师详情 3 个接口：`stats`、`courses`、`students`
- ~~上课记录请假旧前缀：`/assistant/classRecord/leave/*`~~（2026-10-09 已改为 `/teach/leave/*`）
- 课表导出：`/teach/schedule/event/export`
- 点名撤销、导出等写接口

需要：

- 要么补后端
- 要么删除前端 API 桩并改成明确“未接入”
