## 1. 模块概述

### 1.1 业务场景

物品费用管理模块负责管理教育培训机构的物品库存和费用项目,包括:

- **物品管理**: 教材、文具、教具等物品的基本信息管理
- **SKU管理**: 物品的规格、型号、价格等详细信息
- **采购管理**: 物品的采购单据、供应商、支付信息等
- **出入库管理**: 物品的领用、退领、盘点等库存流水记录
- **费用项目管理**: 杂费、活动费、考试费等费用项目
- **费用收取**: 费用的收取记录和统计

### 1.2 核心功能

1. **物品管理**: 创建、编辑、删除物品信息
2. **SKU管理**: 设置物品的多种规格和价格
3. **采购管理**: 创建采购单、记录采购明细、支付信息
4. **出入库**: 记录物品的领用、退领、盘点等库存流水
5. **费用管理**: 创建费用项目,记录费用收取
6. **库存统计**: 统计物品库存和费用收取情况

### 1.3 设计说明

**采购与库存分离设计：**
- **采购单表**：独立管理采购业务，包含财务信息（价格、支付方式、账户等）
- **库存流水表**：仅记录库存数量变化，不包含财务信息
- **关联关系**：库存流水通过 `source_type` 和 `source_id` 关联采购单

**优势：**
- 采购单作为完整的财务单据，便于财务对账和报表统计
- 库存流水表职责单一，仅关注库存数量变化
- 支持采购单的状态管理（草稿、已完成、已取消）
- 便于未来扩展（如采购审批、供应商管理、采购退货等）

|--------|---------|------|------|

| idx_item_type | 普通索引 | item_type | 物品类型查询 |
| idx_status | 普通索引 | status | 状态查询 |

#### 2.1.4 字段说明

**`unit` 字段：** 物品的计量单位，用于标识物品的计量方式
- 常用单位：本、个、套、份、支、张、盒、箱等
- 示例：教材用"本"，文具用"支"，虚拟物品用"份"

**`default_price` 字段：** 默认售卖单价，用于以下场景
- 创建物品时设置的默认售卖价格
- 创建SKU时，SKU的价格默认继承此字段值（可修改）
- 采购时，如果SKU未设置价格，使用此默认价格（采购时可修改实际采购单价）
- 价格优先级：`采购时手动修改的单价 > SKU.price > ast_item.default_price`

**`spec1_name` 和 `spec1_values` 字段：** 规格1配置
- `spec1_name`：规格1的名称，如"颜色"、"尺寸"等
- `spec1_values`：规格1的所有可选值，使用逗号分隔，如"黑色,白色,红色"
- 示例：spec1_name="颜色"，spec1_values="黑色,白色"

**`spec2_name` 和 `spec2_values` 字段：** 规格2配置
- `spec2_name`：规格2的名称，如"码数"、"型号"等
- `spec2_values`：规格2的所有可选值，使用逗号分隔，如"X,L,XL"
- 示例：spec2_name="码数"，spec2_values="X,L,XL"
- 如果物品只有一个规格，spec2_name 和 spec2_values 为 NULL

**规格说明：**
- 教育行业物品规格通常不超过2个维度，采用冗余字段设计更简单高效
- SKU通过规格值的笛卡尔积自动生成
  - 示例1：颜色(黑色,白色) × 码数(X,L) = 4个SKU（黑色X、黑色L、白色X、白色L）
  - 示例2：尺寸(小号,中号,大号) = 3个SKU（小号、中号、大号）
- 如果物品无规格（如教材），spec1_name、spec1_values、spec2_name、spec2_values 均为 NULL，系统自动创建一个默认SKU

#### 2.2.3 索引设计

| 索引名 | 索引类型 | 字段 | 说明 |
|--------|---------|------|------|
| PRIMARY | 主键索引 | id | 主键 |
| uk_sku_no | 唯一索引 | sku_no | SKU编号唯一 |
| idx_item_id | 普通索引 | item_id | 物品ID查询 |
| idx_spec1_value | 普通索引 | spec1_value | 规格1值查询 |
| idx_spec2_value | 普通索引 | spec2_value | 规格2值查询 |
| idx_status | 普通索引 | status | 状态查询 |
| idx_item_spec | 组合索引 | item_id, spec1_value, spec2_value | 复合查询优化 |

#### 2.2.4 字段说明

**`spec1_value` 字段：** 规格1的具体值
- 对应 `ast_item.spec1_name` 的某个值
- 示例：如果 spec1_name="颜色"，则 spec1_value 可能是"黑色"、"白色"等
- 如果物品无规格，此字段为 NULL

**`spec2_value` 字段：** 规格2的具体值
- 对应 `ast_item.spec2_name` 的某个值
- 示例：如果 spec2_name="码数"，则 spec2_value 可能是"X"、"L"、"XL"等
- 如果物品只有一个规格，此字段为 NULL

**SKU命名规则：**
- 双规格：`sku_name = spec1_value + ", " + spec2_value`（如"黑色, X"）
- 单规格：`sku_name = spec1_value`（如"小号"）
- 无规格：`sku_name = "默认"`或物品名称

**查询示例：**
- 查询所有黑色的SKU：`WHERE spec1_value = '黑色'`
- 查询黑色且X码的SKU：`WHERE spec1_value = '黑色' AND spec2_value = 'X'`
- 查询某物品的所有规格1值：`SELECT DISTINCT spec1_value FROM ast_item_sku WHERE item_id = 1 AND spec1_value IS NOT NULL`

**`total_quantity` 和 `total_amount` 字段：** 汇总字段
- 由采购单明细表自动计算汇总
- 便于快速查询采购单的总数量和总金额

**`business_type` 字段：** 业务类型
- purchase：采购入库
- receive：领用出库
- return：退领入库
- inventory：盘点调整

**`stock_before` 和 `stock_after` 字段：** 库存快照
- 记录操作前后的库存数量，便于审计和追溯
- 计算公式：`stock_after = stock_before + quantity`

**`source_type` 和 `source_id` 字段：** 来源单据
- 用于关联业务单据（如采购单）
- 示例：
  - 采购入库：source_type='purchase', source_id=采购单ID
  - 领用出库：source_type='receive', source_id=NULL
  - 退领入库：source_type='return', source_id=NULL
  - 盘点调整：source_type='inventory', source_id=NULL

**`related_type` 和 `related_id` 字段：** 关联角色
- 用于记录领用人、退领人等信息
- 示例：
  - 教师领用：related_type='teacher', related_id=教师ID
  - 学生领用：related_type='student', related_id=学生ID

### 2.7 费用课程关联表 (ast_fee_course)

#### 2.7.1 表基本信息

| 项目 | 内容 |
|------|------|
| 表名 | `ast_fee_course` |
| 说明 | 存储费用与课程的关联关系（多对多） |
| 引擎 | InnoDB |
| 字符集 | utf8mb4 |

#### 2.7.2 字段列表

| 字段名 | 类型 | 长度 | 必填 | 默认值 | 说明 | 字段分类 |
|--------|------|------|------|--------|------|---------|
| `id` | BIGINT | - | 是 | AUTO | 主键ID | 系统字段 |
| `fee_id` | BIGINT | - | 是 | - | 费用ID | 外键字段(ast_fee_item) |
| `course_id` | BIGINT | - | 是 | - | 课程ID | 外键字段(ast_course) |
| `course_name` | VARCHAR | 100 | 否 | NULL | 课程名称(冗余) | 自有字段 |
| `create_by` | VARCHAR | 64 | 否 | '' | 创建者 | 系统字段 |
| `create_time` | DATETIME | - | 否 | CURRENT | 创建时间 | 系统字段 |

#### 2.7.3 索引设计

| 索引名 | 索引类型 | 字段 | 说明 |
|--------|---------|------|------|
| PRIMARY | 主键索引 | id | 主键 |
| uk_fee_course | 唯一索引 | fee_id, course_id | 防止重复绑定 |
| idx_fee_id | 普通索引 | fee_id | 费用ID查询 |
| idx_course_id | 普通索引 | course_id | 课程ID查询 |

#### 2.7.4 字段说明

**`fee_id` 和 `course_id` 字段：** 多对多关联
- 一个费用可以绑定多个课程
- 一个课程可以关联多个费用
- 通过唯一索引 `uk_fee_course` 防止重复绑定

**`course_name` 字段：** 课程名称冗余
- 冗余存储课程名称，便于查询展示
- 减少关联查询的性能开销

**业务示例**：
```
费用：比赛费（¥80）
关联课程：
  - 羽毛球一对一课程
  - 羽毛球一对多课程
  - 羽毛球一对一课程（另一个班级）
```
