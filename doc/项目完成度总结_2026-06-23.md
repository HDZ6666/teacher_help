## 一、总体结论

项目已经从"高保真原型"阶段进入"核心教学链路可用"阶段。教学主链路的后端分层已基本完整，PC 端大部分业务模块已接入真实接口，移动端已有可用的课表/考勤基础。

**三端整体完成度（粗估）：**

- **后端服务**：约 84%（11/13 核心业务分层完整，仅缺上课记录、会员卡）
- **PC 管理端**：约 65%（6 个业务入口中 4 个真实接入，学员列表半 mock，上课记录纯 mock）
- **移动端 uniapp**：约 30%（课表、登录、个人中心、考勤已接真实接口；其余 8 模块未做）

**当前最大缺口（按价值排序）：**

1. **上课记录（classRecord）** —— 前端纯 mock，前端 API 指向 `/assistant/classRecord/*`，但后端**完全没有对应 Controller**，接口悬空。
2. **课表高级交互收尾** —— 课表主体已接入，且已通过 `eventId` 串到班级点名；临时学员、请假、调课、导出等交互仍未闭环。
3. **学员列表去 mock** —— 列表/批量/分配/导入导出仍为占位。
4. **老师管理 PC 入口** —— 后端 CRUD 完整，但 assistant 侧无前端入口。
5. **会员卡、场地管理** —— 仅原型，前后端均未开始。

**结论**：9 个业务 Controller 全部具备 Controller→Service→DAO→Entity 完整四层，核心 service 真实落库（commit/rollback 完整），无大段 TODO/占位。

### 重点接口清单

- **班级** `/teach/class`：list / options / 详情 / 学员列表 / 可加入学员 / 点名准备 / 考勤历史 / 考勤详情 / 增 / 改 / 充值购时 / 加学员 / 提交点名 / 删学员 / 删班级
- **排课** `/teach/schedule/event`：list / 详情 / 日历事件(FullCalendar) / 增 / 改 / 删
- **考勤** `/teach/schedule/attendance`：list / 签到 checkin / 手动补录 manual / 统计 stat
- **学员** `/teach/student`：list / enroll 报名续费 / 课程账户 / 订单 / 详情 / 增改删 / 导出
- **课程** `/teach/course`：课程 CRUD + 批量 + 启停 + 导出 + 课程选项 + 套餐 CRUD/启停
- **物品费用** `/ast/item`、`/ast/inventory`：物品/SKU + 库存流水 + 采购/导入 + 领用/退领 + 盘点 + 费用 CRUD

### 数据库迁移

`module_teach/schema.py`（启动时 `init_create_table` 自动执行）为 MySQL 补齐：
- `teach_schedule_events` 增列：course_id / course_name / class_id / class_name / classroom / lesson_hours / content
- `teach_class_attendance` 增列：event_id（关联排课事件）

> 说明：`event_id` 列已被 PC 端用于“课表课次 -> 班级点名 -> 同步课次统计”的基础链路；PC 课表页暂未直接调用 `/teach/schedule/attendance`，而是通过班级点名接口桥接。

### 后端缺口

- 🔴 **上课记录**：无 `classRecord` Controller/Service/表。当前由 `schedule_event + schedule_attendance` 部分代替，但缺点评、请假申请、缺课补课、缺课提醒、超时未点名等独立业务。
- 🔴 **会员卡**：完全不存在（无充值、余额、有效期、消费抵扣）。
- 🟡 **场地管理**：未做独立模块，用排课/班级表的 `classroom` 字符串字段代替。

5. 🟡 **学员列表 mock** —— 列表/分配/导入导出/批量更新占位。
6. 🟡 **老师管理缺 PC 入口** —— 后端 CRUD 就绪，assistant 无导航入口与详情统计/权限联动。
7. ⬜ **会员卡、场地管理** —— 前后端均未开始。
8. ⚠️ **大批未提交代码** —— 班级模块（`teach_class_controller/dao/service/vo/do`、`schema.py`、`class.js` 等）及报名相关改动仍处未跟踪/未提交状态，建议尽快 review 并入库，避免丢失。
