# 学员管理模块 PC 端业务闭环分析

> 分析范围：`doc/产品图片/1学员管理模块`、`doc/01_学员管理模块总结报告.md`、PC 端 `assistant/student` 与 `teach/student`、后端 `module_teach`  
> 分析结论：当前 PC 端尚未形成学员管理完整业务闭环，仅基础学生档案 CRUD 有真实接口雏形。

## 1. 产品图片体现的业务模型

产品图片中的“学员管理”不是单一学生表，而是一个学员生命周期管理模块，核心由以下几条链路组成：

1. 学员档案链路  
   在读学员列表支持搜索、筛选、导入、导出、分配跟进人、分配学管师、批量操作。学员资料包含姓名、手机号、来源、年龄、生日、班级、年级、学校、标签、跟进人、学管师、创建人等。

2. 报名/续费链路  
   从学员详情进入报名，选择课程、套餐、物品、费用，设置定价标准、购买数量、赠送数量、优惠/折扣、经办日期、业绩归属人、支付信息，最后确认报名。

3. 报读与课时账户链路  
   报读情况页面展示购买数量、赠送数量、已消耗数量、退转数量、剩余数量、课消金额、剩余课消金额、到期日期、缺课次数、跟进人、学管师等。

4. 课务变更链路  
   支持批量课时清零、批量转课、批量结课、批量停课、批量复课、批量修改有效期、修改请假免扣次数、超上课时处理等。

5. 学员详情总览链路  
   学员详情中聚合报读课程、充值账户、持有卡项、跟进管理、消费记录、上课记录、考勤记录、成长档案、学习报告等。

6. 财务与记录链路  
   报名后生成订单、消费记录和收据；消费记录中可查看订单状态、订单类型、购买项目、应收/实收/退款、订单来源，并支持打印收据、继续收款等操作。

7. 教学执行回流链路  
   班级、课表、上课记录和考勤结果会回流到学员详情，形成课程消耗、上课记录、考勤记录和课后服务记录。

## 2. 总结报告中的闭环要求

`doc/01_学员管理模块总结报告.md` 对该模块的定位是：

- 学员档案：单个建档、Excel 批量导入。
- 报名订单：选择课程、套餐、物品、费用后生成订单。
- 跟进记录：记录跟进方式、阶段、内容、附件和下次跟进时间。
- 课务变更：请假、调课、转课、停课、结课、课时清零、有效期修改。
- 收据/消费记录：报名确认后生成消费记录，可查看或打印收据。
- 数据回流：上课、点名、点评、缺课、补课、请假沉淀到学员详情。

换句话说，判断“业务闭环”不能只看是否有学生列表和新增按钮，而要看至少能否完成：

```text
建档 -> 报名收费 -> 生成报读/课时账户 -> 入班/排课 -> 点名消课 -> 回写详情/消费/上课记录 -> 支持转课/停课/结课等变更
```

## 3. 数据模型对照

数据库设计文档 `doc/数据库设计/01-学员管理模块数据库设计.md` 中规划的核心表包括：

- `ast_student`：学员基本信息。
- `ast_student_contact`：学员联系人。
- `ast_student_tag`：学员标签。
- `ast_student_course_account`：学员课时账户。
- `ast_enrollment_order`：报名订单主表。
- `ast_enrollment_order_item`：报名订单明细。
- `ast_order_performance`：订单业绩归属。

当前后端实际实现集中在 `module_teach`：

- `teach_students`：学生基础信息。
- `teach_parents`、`teach_base_users`：家长与基础用户。
- `teach_schedule_events`、`teach_schedule_attendances`：排课与考勤。

当前后端尚未看到与产品图完全对应的 `ast_student`、报名订单、订单明细、课时账户、联系人、标签、跟进记录等学员管理核心表和接口。

## 4. PC 端现状

### 4.1 `teach/student`：基础学生 CRUD

路径：

- `teacher_help_admin/src/views/teach/student/index.vue`
- `teacher_help_admin/src/views/teach/student/detail.vue`
- `teacher_help_admin/src/api/teach/student.js`
- `teacher_help_service/module_teach/controller/teach_student_controller.py`

已具备：

- 学生列表查询。
- 学生详情。
- 新增学生。
- 修改学生。
- 删除学生。
- 导出学生数据。
- 关联家长列表。

不足：

- 这是“学生基础资料”管理，不是产品图中的完整“学员管理”。
- 详情页的报读课程接口 `getStudentCourses()` 目前直接 `Promise.resolve({ data: [] })`。
- 退课 `withdrawCourse()` 也是前端假成功。
- 无报名订单、课时账户、消费记录、收据、跟进、持有卡、充值账户等闭环数据。

### 4.2 `assistant/student`：贴近产品图的业务页面

路径：

- `teacher_help_admin/src/views/assistant/student/index.vue`
- `teacher_help_admin/src/views/assistant/student/detail.vue`
- `teacher_help_admin/src/views/assistant/student/enroll.vue`

已具备的页面形态：

- 在读学员 / 报读情况两个 Tab。
- 学员列表、报读情况列表、分配跟进人、分配学管师、导入、导出、更多操作入口。
- 学员详情页，展示报读课程、充值账户、持有卡项、跟进管理、消费记录、上课记录、考勤记录、成长档案、学习报告等 Tab。
- 报名/续费页，支持选择课程、物品、费用，并做前端金额、数量、赠送、有效期等计算。

核心问题：

- 列表数据是 `setTimeout + mockData`。
- 报读情况数据是 `mockEnrollmentData`。
- 跟进人、学管师列表是模拟数据。
- 导入学员、导入报读信息、批量更新、导出详情、编辑报读信息均提示“功能开发中”。
- 学员详情中的充值账户、持有卡项、跟进管理、消费记录、上课记录、考勤记录、成长档案、学习报告均提示“功能开发中”。
- 报名确认处明确写着“这里应该调用API提交报名信息”，当前只是 `console.log` 后提示成功。
- 学员详情也是模拟数据，不从后端读取真实聚合数据。

## 5. 闭环判断

| 业务点 | 产品要求 | PC 当前状态 | 闭环状态 |
|---|---|---|---|
| 学员建档 | 新增/导入学员，维护完整资料 | `teach/student` 有新增/编辑/删除；`assistant/student` 为模拟 | 部分闭环 |
| 学员导入 | 支持多个 Excel 模板导入 | 只有按钮和提示 | 未闭环 |
| 分配跟进人/学管师 | 批量分配并持久化 | 弹窗和模拟操作 | 未闭环 |
| 报读情况 | 展示真实报读课程、课时、金额、有效期 | `assistant/student` 模拟列表 | 未闭环 |
| 报名/续费 | 选择课程/物品/费用/套餐并生成订单 | 页面交互较完整，但无提交 API | 未闭环 |
| 订单/收据/消费记录 | 报名后生成订单、消费记录、收据 | 详情 Tab 未实现 | 未闭环 |
| 课时账户 | 报名后生成课时账户，点名后扣课 | 后端未见课时账户模型 | 未闭环 |
| 转课/停课/结课/清零 | 高影响课务变更并留痕 | 仅页面入口或截图要求，当前未实现 | 未闭环 |
| 跟进记录 | 新增跟进记录并形成历史 | 详情 Tab 未实现 | 未闭环 |
| 上课/考勤回流 | 点名和考勤回写学员详情 | 后端有排课/考勤基础，但未和学员详情闭环 | 未闭环 |
| 持有卡/充值账户 | 学员权益与财务账户展示 | 详情 Tab 未实现 | 未闭环 |

## 6. 总体结论

当前 PC 端没有完成“学员管理模块”的业务闭环。

更准确地说：

- `teach/student` 完成了基础学生档案 CRUD 的接口雏形，可以作为学员档案能力的起点。
- `assistant/student` 已经把产品图中的主要交互和页面结构搭出来了，但大多是原型态，未接入真实后端。
- 后端当前没有完整承载产品图所需的学员生命周期数据模型，尤其缺报名订单、订单明细、课时账户、跟进记录、联系人、标签、收据/消费记录等核心接口。

因此，当前状态应判定为：

```text
页面原型完整度：中高
基础学生 CRUD：部分可用
学员业务闭环：未完成
```

## 7. 建议下一步

建议先确定学员模块的数据口径：是继续使用当前 `teach_students` 体系扩展，还是按数据库设计文档落 `ast_student` / `ast_enrollment_order` / `ast_student_course_account` 体系。

若目标是复刻产品图闭环，建议按以下顺序推进：

1. 学员主档：补齐联系人、标签、来源、跟进人、学管师字段和接口。
2. 报名订单：新增订单主表、订单明细、业绩归属、支付信息接口。
3. 课时账户：订单支付成功后生成课时账户。
4. 报读情况：用订单明细 + 课时账户驱动列表。
5. 学员详情：聚合报读课程、消费记录、上课记录、考勤记录、跟进记录。
6. 课务变更：实现转课、停课、结课、课时清零、有效期修改，并补操作日志。
7. 将 `assistant/student` 的 mock 数据替换成真实 API。
