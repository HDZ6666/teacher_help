## 1. 引言

### 1.1 项目背景
在“双减”政策背景下，教培行业涌现出大量独立运营的教师。他们虽具备专业的教学能力，但普遍缺乏系统化的教务、财务和学生管理工具，导致工作效率低下，难以规模化发展。本项目旨在开发一款名为“老师帮”的APP，为独立教师提供一个轻量级、智能化的一站式管理解决方案。

### 1.2 项目目标
- **提升效率**：通过自动化和智能化的工具，将独立教师从繁琐的行政事务中解放出来，使其能更专注于教学本身。
- **提升质量**：提供错题本、教学资源等辅助工具，帮助教师提升教学效果和学生满意度。
- **增强连接**：建立便捷的家校沟通渠道，帮助教师维护私域流量，增强用户粘性，促进口碑传播和续费。
- **保障合规**：产品设计遵循相关政策法规，辅助教师合规运营。

### 1.3 目标用户
- **核心用户**：教培行业的独立教师、小微型工作室创始人。
- **次要用户**：学生家长（通过APP接收通知、查看进度等）。

## 2. 整体需求

### 2.1 产品定位
一款专为独立教师打造的，集排课、考勤、学生管理、教学辅助和家校沟通于一体的**轻量级、智能化移动工作台**。

### 2.2 设计原则
- **简洁易用 (Simplicity)**：界面清晰，操作流程直观，零学习成本，解决教师技术接受度不一的问题。
- **高效智能 (Efficiency & Intelligence)**：自动化处理重复性工作（如排课冲突检测、收费提醒），提供智能建议（如复习建议）。
- **连接与信任 (Connection & Trust)**：强化家校沟通功能，让教学过程透明化，建立家长信任。
- **安全可靠 (Security & Reliability)**：保障师生数据和隐私安全，确保系统稳定运行。

## 4. 非功能性需求 (Non-Functional Requirements)

| 需求类别 | 详细要求 |
| :--- | :--- |
| **性能** | - APP启动时间 < 3秒。<br>- 核心页面加载时间 < 2秒。<br>- 列表滑动流畅，无明显卡顿。 |
| **易用性** | - 首次登录有核心功能引导。<br>- 界面布局符合主流APP使用习惯，功能入口清晰。<br>- 核心操作（如排课、签到）能在3步内完成。 |
| **可靠性** | - 服务可用性 > 99.5%。<br>- 用户数据每日自动备份，防止数据丢失。 |
| **安全性** | - 用户密码、支付信息等敏感数据需加密存储。<br>- 通信协议使用HTTPS。<br>- 严格遵守用户隐私协议，不得滥用学生和家长信息。 |
| **兼容性** | - 支持主流的iOS和Android系统版本（如近3年的版本）。<br>- 良好适配不同尺寸的主流手机屏幕。 |

## 5. 需求优先级 (MVP划分)

为了实现快速上线和市场验证，建议按以下优先级进行分期开发：

- **P0 (MVP核心功能)**：**必须包含，构成产品最小闭环。**
  - **模块**：课程与排课管理、签到与考勤管理、学生管理与家长沟通（家长作为联系人和通知对象）。
  - **目标**：解决独立教师最核心的排课、签到、学生管理和家校沟通痛点，实现基础的教务管理。

- **P1 (重要功能)**：**MVP版本上线后，快速迭代开发。**
  - **模块**：错题本管理、财务管理、数据分析看板。
  - **目标**：打造产品差异化优势（错题本），完善商业闭环（财务），并通过数据赋能教师运营。

- **P2 (拓展功能)**：**产品成熟后，根据用户反馈和市场情况规划。**
  - **模块**：教学资源中心、更高级的智能推荐功能。
  - **目标**：构建教学内容生态，进一步提升用户粘性。

## 6. 附录：用户故事示例

- **作为一名独立数学老师：**
  - 我希望**能通过日历快速查看我一周的所有课程**，这样我就能合理安排我的备课和休息时间。
  - 我希望**在给学生排补课时，系统能自动提示我哪些时间段是空闲的**，这样就不用我费力地去翻找记录。
  - 我希望**每次学生扫码签到后，他/她的家长能立即收到一条通知**，这样不仅能减少我的沟通成本，还能让家长觉得服务很到位。

- **作为一名学生家长：**
  - 我希望**能随时在APP上查看孩子剩余的课时**，这样我就能及时续费，避免课程中断。
  - 我希望**每次课后能收到老师发的简短课堂报告**，这样即使我很忙，也能了解孩子的学习情况。
